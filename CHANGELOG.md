# Журнал изменений

Все заметные изменения SDK — здесь. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — SemVer (см. «Совместимость и версии» в README).

## [0.1.1] — 2026-11-21

### Исправлено

- Вход пользователя (`identify`), при котором гостевая переписка устройства сливается в беседу
  пользователя: своё сообщение, отправленное прямо перед входом или во время него, больше не теряется.
  Лента сменяется на беседу пользователя, а своё неподтверждённое сообщение остаётся в её конце и
  доставляется — без дублей и без `SendFailed`. При входе другого пользователя на устройстве
  неотправленное прежнего по-прежнему не переносится (`SendFailed("identity_changed")`).
- Короткий перезапуск сервера (закрытие живой ленты кодом 1001/1012 или обрыв транспорта) больше не
  показывает мгновенное «Нет соединения»: состояние — `Connecting`, `Offline` — только если сеть
  пропала или сервер не поднялся за 20 с. Таймауты HTTP-запроса — 60 с вместо 15.

### Изменено

- Готовый экран: тяжёлые фото перед отправкой ужимаются (JPEG 0,8, до 5 Мп / 4096 px по длинной
  стороне; скриншоты телефона — без уменьшения; PNG с прозрачностью и анимация — как есть).
  Геометка из фото не уходит, ориентация сохраняется. На плашке вложения — индикатор загрузки.

## [0.1.0] — 2026-09-24

### Формат токена identify

- Токен личности — формата identify v2: необязательные claims названы как в OpenID Connect
  (`phone_number` в E.164 вместо прежнего `phone`, который сервер игнорирует; `email_verified`,
  `phone_number_verified`, `amr`, `idp`, `auth_time`, `ids`). Поле неверного вида вход не роняет —
  сервер его не сохраняет; `422` — только по безопасности токена. Один токен — один вход: новый токен
  с `jti` на каждый запрос SDK. Токен выпускает ваш бэкенд, SDK его не разбирает — меняется только
  бэкенд интегратора. Подробно — «Личность пользователя» в README.

### Добавлено

- Продукт `RevbackChatCore` — ядро без единого экрана: стабильный id визитёра, пуши и счётчик
  непрочитанного, лента, отправка, вложения, `identify` по токену (JWT HS256), который выпускает ваш
  бэкенд, атрибуты.
- Продукт `RevbackChatUI` — готовый экран чата на SwiftUI поверх ядра (`RevbackChatView` /
  `RevbackChatViewController`); ядро подключается вместе с ним автоматически.
- Меню вложений в готовом экране: скрепка открывает «Фото и видео» (`PHPickerViewController`) и
  «Файл» (`UIDocumentPickerViewController`); разрешений и строк `NS…UsageDescription` не требуется.
- Подключение через Swift Package Manager; системную `libsqlite3` пакет линкует сам — с любым из
  двух продуктов.
- Требования: iOS 15 и выше, Swift tools 5.9.
- Privacy manifest (`PrivacyInfo.xcprivacy`) в XCFramework ядра и в пакете: без трекинга, без
  required-reason API, собираемые данные — только ради работы чата (см. «Privacy manifest» в README).
- Бейдж непрочитанного: листенер `setUnreadListener`, поставленный после того, как число стало известно, сразу
  получает текущее число — ставить его можно когда угодно, бейдж на холодном старте не пустует до ответа сервера.
- Выход пользователя (`reset()`) переживает смерть процесса: если приложение убили посреди выхода, SDK сам
  стирает данные прежнего пользователя на следующем старте и позже снимает его пуш-подписку и сессию на сервере.
- Переустановка приложения без выхода: подтверждённая личность после переустановки сбрасывается — SDK сам
  стирает такую сессию и данные визитёра на устройстве на первом запуске, как `reset()`, но без события
  `ChatEvent.Reset` приложению; сессию на сервере SDK отзывает отложенной уборкой, когда ответит сеть. Переписка
  клиента вернётся после `identify`; анонимный гость продолжает беседу. Приложению ничего делать не нужно.
- `RevbackChat.shared.setPushToken(token:provider:)`: `PushProvider` — открытый набор, а не enum:
  `PushProvider.companion.Fcm`, `Apns`, `Rustore`, `Hms`, сравнение по равенству; провайдер, которого версия SDK
  ещё не знает, — `PushProvider.companion.fromWire(value:)`. Сервер провайдера не принимает — один откат на `fcm`
  и `TelemetryEvent.PushProviderFallback`.
- Разбор пуша `RevbackChat.shared.handlePush(data:)` — `PushAction`: `ShowMessage`, `TestPush`, `Suppress`,
  `Ignore` (наш пуш, показывать нечего — в том числе пуш операторской части RevBack), `NotOurs` (пуш приложения).
- Превью вложений: `FileSource.withPreview(preview:)` — превью собирается цепочкой `MediaPreview()`,
  `withThumbnail(bytes:mime:)`, `withDurationMs(ms:)`, `withSize(width:height:)` (обложка — вместе с типом, ширина —
  вместе с высотой); обложка видео уходит второй загрузкой (её сбой
  сообщение не валит), длительность и размеры — вместе с сообщением; у `Attachment` — `thumbnailBlobRef`,
  `durationMs`, `width`/`height`, обложка — `conversation.attachmentThumbnail(...)`. `attachmentBytes` отдаёт и
  свои вложения (после переустановки, на другом устройстве). Кэш переписки обновляется миграцией — неотправленное
  и локальные файлы сохраняются.
- Поле ввода готового экрана предлагает заглавную букву в начале предложения, как в мессенджерах.
- Готовый экран: выбранные файлы над полем ввода — плитки фото и видео с миниатюрой (у видео — «плей» и
  длительность) и карточки документов с именем и размером; видео в ленте — обложка с «плей» и длительностью, место
  под фото и видео занимается до загрузки, лента не прыгает; открыли чат без сети — обложки подтянутся, когда связь
  вернётся. Кадр и длительность экран снимает сам при выборе файла.
  Свои вложения без локальной копии (после переустановки, с `persistHistory = false`) подтягиваются с сервера —
  сразу, как только сервер подтвердил отправку.
- `RevbackChat.shared.config` — настройка, с которой работает SDK (только чтение, `nil` до `configure`). Файлы
  вложений, которые SDK хранит на устройстве, удаляются при выходе пользователя, а с `persistHistory = false` — и на
  каждом старте. Готовый экран при `persistHistory = false` не оставляет на диске копий выбранных файлов — превью
  при этом не пропадает; с хранением истории копии занимают не больше 50 МБ.
- Готовый экран: фото HEIC с iPhone (и другие картинки в форматах, которые сервер не показывает как картинку) перед
  отправкой перекодируются в JPEG с правильным поворотом и уходят фото, а не файлом. Картинка ужимается до 4096
  пикселей по большей стороне; с настоящей прозрачностью — PNG, а если PNG больше потолка размера файла — JPEG на
  белом фоне. Снимок уходит одинаково из «Фото и видео» и из «Файл». Картинки в форматах, которые сервер показывает
  как картинку, уходят как есть, любого размера в пикселях, если файл укладывается в потолок размера; неподвижная
  картинка больше потолка (JPEG, PNG, HEIC и др.) ужимается до 4096 пикселей и уходит, если ужатое влезло.
